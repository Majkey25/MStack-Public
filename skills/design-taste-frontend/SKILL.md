# Design taste for frontend

Identify the audience, the primary action, and what existing behavior must survive. Start with the project's design system, assets, and real content. For a redesign, capture the current page and note which parts work before editing.

- Make the first screen communicate the page's purpose and primary action. Choose a clear typographic hierarchy and one visual focal point. Keep decorative copy and badges only when they carry information.
- Give each section a job. Use structure that fits the content and keep spacing consistent across shared edges. Balance content density, contrast, and readable line lengths at narrow and wide widths.
- Use recognizable controls for the important actions. Show focus, errors, and loading states. Use motion for continuity or feedback, and support reduced motion.
- In a real browser, compare wide and narrow layouts, inspect long content and keyboard navigation, and verify the main interaction. Compare redesign screenshots in the same state and viewport. Fix material issues and recapture.

Keep the user's brand and constraints. Explain design decisions by pointing to the visible result or behavior they improved.
